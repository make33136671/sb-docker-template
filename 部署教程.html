SB Framework Docker 部署教程

单容器部署 · 使用 deploy.sh 一键部署 · 无需手动编辑配置文件

前提条件

  • 服务器已安装 Docker 和 Docker Compose
  • 服务器开放端口 8080（用户端）、8081（管理端）、8082（API）
  • 如需使用域名：宿主机已安装 Nginx 并配置好域名解析和 SSL 证书
! 如果服务器 80 端口已被宿主机 Nginx 占用，Docker 容器使用 8080/8081/8082 端口，由宿主机 Nginx 反代到这些端口。

0准备编译产物

部署前需要将以下编译产物放入部署包对应目录：

目录内容构建命令示例
admin-ui/html/ Admin 前端构建产物 pnpm build → 复制 dist/ 内容
user-ui/html/ 用户端前端构建产物 pnpm build → 复制 dist/ 内容
api/app/ .NET API 发布产物 dotnet publish -c Release -o api/app
i 确保前端构建时 API 请求路径使用相对路径（/admin/、/user/ 等），避免 CORS 问题。

1首次部署

将部署包上传到服务器后，执行以下命令：

# 解压部署包
tar -xzf myapp-docker.tar.gz
cd myapp-docker

# 一键部署（自动生成 .env 配置文件）
bash deploy.sh

首次运行 deploy.sh 会生成 .env 文件并提示你修改项目配置：

# 修改 .env 中的以下两项为你的项目实际值
PROJECT_NAME=myapp              # 你的项目名
APP_DLL_NAME=MyApp.WebApi.dll   # 你的 API DLL 文件名

修改后再次运行 bash deploy.sh，它会自动完成：

  • 生成 24 位高强度 PostgreSQL 密码
  • 构建 Docker 镜像（首次约 3~5 分钟）
  • 启动容器并等待服务就绪
✓ 部署完成后，终端会显示 PostgreSQL 密码，请务必记录。密码也可在 .env 文件中查看。

2重新部署（更新版本）

当有新版本代码需要更新时，使用 redeploy.sh 一键重新部署：

# 上传新的部署包并解压
tar -xzf myapp-docker.tar.gz
cd myapp-docker

# 将旧 .env 复制过来（保留原有的数据库密码和配置）
cp ../myapp-docker/.env . 2>/dev/null || true

# 一键重新部署
bash redeploy.sh

redeploy.sh 会自动完成：

  • 停止并删除旧容器
  • 使用 --no-cache 重新构建镜像
  • 启动新容器并等待服务就绪
i 重新部署前请确保 .env 文件存在且数据库密码与首次部署一致，否则数据将无法访问。

!彻底清除并重新部署

当遇到严重问题需要从零开始时，可以彻底删除所有容器、数据卷和镜像，然后全新部署。

!! 警告

此操作将永久删除所有数据，包括：

  • PostgreSQL 数据库中的全部数据（管理员、业务数据等）
  • Redis 缓存数据
  • Docker 命名卷中的所有持久化数据
  • 已安装的系统配置（installed.lock）

此操作不可恢复！执行前请务必备份重要数据！

如仅需更新代码版本（保留数据），请使用上方的「重新部署」而非此方法。

确认已备份并需要彻底清除后，执行以下命令：

# 1. 进入部署目录
cd myapp-docker

# 2. 停止并删除容器 + 所有数据卷
docker compose down -v

# 3. 删除旧镜像
docker rmi $(docker images -q myapp-docker 2>/dev/null) 2>/dev/null
docker image prune -f

# 4. 删除整个旧部署目录
cd ..
rm -rf myapp-docker

# 5. 上传新的 myapp-docker.tar.gz 并解压
tar -xzf myapp-docker.tar.gz
cd myapp-docker

# 6. 全新部署
bash deploy.sh
✓ docker compose down -v 中的 -v 参数会删除所有命名数据卷。部署完成后安装向导会以全新状态启动，deploy.sh 会生成新的数据库密码。

配置说明（.env 文件）

所有配置通过 .env 文件管理，不建议手动编辑 docker-compose.yml 或其他配置文件。

.env 文件由 deploy.sh 自动生成，内容如下：

# 项目名（影响容器名、数据库名、Redis前缀）
PROJECT_NAME=myapp

# API DLL 文件名（改为你的项目实际 DLL 名）
APP_DLL_NAME=MyApp.WebApi.dll

# 对外端口（三端口分离）
USER_PORT=8080
ADMIN_PORT=8081
API_PORT=8082

# PostgreSQL（密码已自动生成）
POSTGRES_DB=sb_myapp
POSTGRES_PASSWORD=AutoGenerated24CharPassword

# 数据持久化
# 留空 = Docker 命名卷（内置）
# 填路径 = 绑定挂载到宿主目录（外置）
POSTGRES_DATA_PATH=
REDIS_DATA_PATH=

可调整的配置项

变量默认值说明
PROJECT_NAMEmyapp项目名（影响容器名、数据库名、Redis前缀）
APP_DLL_NAMEMyApp.WebApi.dllAPI DLL 文件名
USER_PORT8080用户端对外端口
ADMIN_PORT8081管理端对外端口
API_PORT8082API 对外端口
POSTGRES_DBsb_myapp数据库名称
POSTGRES_PASSWORD自动生成数据库密码（勿修改）
POSTGRES_DATA_PATH留空填路径则数据外置到宿主目录
REDIS_DATA_PATH留空填路径则 Redis 数据外置到宿主目录

端口与服务说明

端口服务容器内路径说明
8080 用户端 UI /app/user-ui 面向终端用户的前端页面
8081 管理端 UI /app/admin-ui 后台管理界面 + 安装向导
8082 API 服务 /app/api .NET API 直通（SignalR + REST）

容器内部还运行着 PostgreSQL 和 Redis，但不对外暴露端口，仅在容器内部通信。

域名与 SSL 配置（宿主机）

域名和 SSL 在宿主机 Nginx 层配置，容器不参与。以下为参考配置：

# 宿主机 /etc/nginx/conf.d/your-domain.conf

# 管理端 — admin.yourdomain.com
server {
    listen 443 ssl;
    server_name admin.yourdomain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# 用户端 — yourdomain.com（主域名）
server {
    listen 443 ssl;
    server_name yourdomain.com www.yourdomain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8082;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com admin.yourdomain.com;
    return 301 https://$host$request_uri;
}

系统安装向导

首次访问管理端时，系统会自动跳转到安装向导页面。

Docker 部署模式（自动检测）

安装向导会自动检测 Docker 环境并预填以下默认值：

  • 数据库类型：PostgreSQL（MySQL 选项已隐藏）
  • 数据库地址：127.0.0.1:5432
  • 数据库名：deploy.sh 生成的值（如 sb_myapp）
  • 数据库用户：postgres
  • 数据库密码：deploy.sh 自动生成的密码（已预填）
  • 站点路径：/app/admin-ui 和 /app/user-ui（可修改）
  • API 路径：/app/api（自动探测）
✓ Docker 模式下，数据库配置已全部预填，通常无需修改，直接点击「下一步」即可。

传统部署模式

非 Docker 环境下，安装向导保持原有行为：数据库默认 MySQL（可选 PostgreSQL），路径根据 API 目录自动推断。

常用运维命令

# 查看容器状态
docker compose ps

# 查看实时日志
docker compose logs -f

# 重启容器
docker compose restart

# 停止容器
docker compose down

# 启动容器（不重新构建）
docker compose up -d

# 进入容器
docker compose exec app bash

# 查看容器内服务状态
docker compose exec app supervisorctl status

# 查看数据库密码
grep POSTGRES_PASSWORD .env

常见问题

Q: 端口 8080/8081/8082 被占用怎么办？

编辑 .env 文件修改对应端口号，然后运行 docker compose up -d 重启。

Q: 忘记数据库密码怎么办？

在部署目录运行 grep POSTGRES_PASSWORD .env 即可查看。密码在首次部署时由 deploy.sh 自动生成。

Q: 如何将数据外置到宿主机？

编辑 .env，设置 POSTGRES_DATA_PATH=./data/postgres 和 REDIS_DATA_PATH=./data/redis，然后 docker compose up -d。

Q: 重新部署后数据会丢失吗？

不会。只要 .env 中的 POSTGRES_PASSWORD 和 POSTGRES_DB 与首次部署一致，Docker 命名卷会保留数据。redeploy.sh 会自动复用 .env。

Q: 安装向导页面打不开？

检查容器是否正常运行（docker compose ps），以及 Nginx 是否正确代理到 8081 端口。等待约 15 秒让所有服务启动。
